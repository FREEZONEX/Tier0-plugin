# Tier0 平台插件

安装并加载后，在 AI 助手的新对话中说“连接 Tier0”或“查看 Tier0 的 UNS 数据”。首次调用会检查 CLI 与登录状态；需要登录时给出授权链接，由用户在 Tier0 浏览器页面登录、选择工作区并授权。身份验证成功后继续原任务。已登录用户复用现有授权。

## 当前支持

- 连接与诊断：CLI 安装、浏览器授权、用户/工作区/权限查询、服务信息。
- UNS：浏览、搜索、读写、历史数据、节点管理。
- Flow：SourceFlow/EventFlow 管理、Node-RED 画布导出与部署。
- MQTT：凭证管理、消息发布、有界订阅。
- 文件：上传、下载、获取访问地址、删除。
- 成员查询：仅限已确认支持对应接口的部署。

暂不支持应用生成、Scaffold 初始化、App 源码上传、建版与发布。Flow 部署不等于 App 发布。

## 实现

包含一个 `platform` 技能、现有 Tier0-skill 的业务参考，以及安全输出包装脚本。实际请求与凭证保存由现有 Tier0 CLI 负责；没有新增平台 API、MCP 服务或认证协议。安装插件本身不会触发登录；首次使用才引导鉴权。

需要 Python 3 与 Tier0 CLI。缺少 CLI 时引导运行官方 `npx -y @tier0/cli@0.7.0 install`（Node.js >=16）。安装器会写入 ~/.tier0 并同步上游独立 Skills；本插件参考资料独立随插件升级。登录与 MQTT 凭证创建的原始输出可能包含密钥，插件脚本仅返回允许展示的字段。

凭证由 CLI 保存在用户目录，不在插件内；卸载插件不等于撤销平台 Key。当前 CLI 没有 logout 命令，远端撤销须在平台实际 API Key 管理入口完成。

## 验证

- 插件清单与技能格式校验通过。
- 16 项模拟鉴权/凭证输出测试通过，覆盖密钥不回显、超时、业务错误、实例不符、缺 CLI/登录以及身份复核失败。
- 实际 CLI 0.7.0 的 help 和 5 项离线 dry-run 通过：UNS 写入/创建、Flow 创建、文件删除、MQTT 凭证创建。
- 本机安全状态检查返回 login_required。尚未进行真实用户浏览器授权与平台业务联调；dry-run 不证明平台执行成功。
